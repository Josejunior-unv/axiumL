Projeto 01 · Previsão de churn

Fatura de Risco

Como o modelo estima a chance de um cliente de telecom cancelar o plano e decide para quem vale a pena oferecer um desconto de retenção.

  • Base7.000 clientes
  • Teste1.400
  • Modeloregressão logística
  • ROC-AUC no teste0,835
  • Limiar0,36
O problema

Um em cada quatro clientes vai embora

Na base de 7.000 clientes, 27,4% cancelaram o plano. Ao lado estão 420 clientes do conjunto de teste; os vermelhos cancelaram.

O projeto tem dois objetivos: estimar a chance de cada cliente cancelar e decidir para quem compensa oferecer um desconto de retenção.

Pipeline

Do cadastro à probabilidade

O modelo recebe só os campos do cadastro. Dentro do pipeline do scikit-learn, três variáveis novas são calculadas: o logaritmo do tempo de casa, o gasto médio por mês e um indicador de cliente novo.

Depois, os números vão para a mesma escala e cada categoria vira uma coluna de 0 e 1. A regressão logística soma tudo com pesos aprendidos e a função sigmoide transforma a soma num valor entre 0 e 1.

Explicação

Cada previsão vira uma fatura

Como o modelo é linear, a previsão pode ser escrita como uma conta: parte do cliente médio do treino, e cada característica acrescenta ou desconta log-chance. O total passa pela sigmoide e vira probabilidade.

Contrato
Seleção do modelo

Cinco rodadas de validação

Para escolher o modelo sem olhar o teste, o treino (5.600 clientes) é dividido em 5 partes. Cada parte serve uma vez de validação enquanto os modelos treinam nas outras quatro.

A regressão logística vence o gradient boosting nas cinco rodadas, porque os dados foram gerados por um processo quase logístico. As previsões feitas fora da amostra ficam guardadas: é com elas que o limiar será escolhido.

Decisão

Quanto vale avisar

Cada oferta custa R$ 120. Se o cliente ia mesmo sair, a oferta o segura em 30% dos casos e preserva um ano de mensalidade. Quem fica abaixo do limiar não recebe nada.

O limiar 0,36 maximiza o lucro nas previsões fora da amostra do treino. No teste, ele rende R$ 44.489. Oferecer para todos daria prejuízo de R$ 31.559.

Explicabilidade

O que mais pesa

Para medir a importância de uma variável, a coluna dela é embaralhada no teste e mede-se quanto a ROC-AUC cai. Se o modelo dependia dela, a previsão piora muito.

Tempo de casa e tipo de contrato dominam. O total gasto aparece forte porque carrega quase a mesma informação que o tempo de casa: ele é a mensalidade multiplicada pelos meses.

Produção

A mesma conta, servida por uma API

A API FastAPI recebe os campos brutos em JSON, roda o mesmo pipeline salvo pelo treino e devolve a probabilidade e a decisão de acionar a retenção.

O exemplo usa o cliente montado no simulador. Para subir a API: python -m churn.treinar e depois uvicorn churn.api:app.

Todos os números vêm do projeto projetos-ia/01-previsao-churn rodado com semente 42 e foram exportados por animacao/exportar_dados.py.
Os clientes são sintéticos: o gerador sorteia o churn a partir de efeitos conhecidos, para dar para conferir o que o modelo aprende.
